# Три стратегии управления контекстом

Пятница второй недели. За основу взято только [задание четверга](../thu/README.md):
CLI, Flask, SQLite, учёт токенов и очистка reasoning в ответах.
Сжатие через summary заменено на Sliding Window и Sticky Facts; добавлен Branching.

## Запуск

Из `Week_2/fri`, Python 3.10+:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Заполните .env своим ключом и моделью.
set -a
source .env
set +a
python web.py
```

Веб: <http://127.0.0.1:5000>. CLI: `python cli.py`.
Используйте отдельную базу пятницы: импорт баз других заданий не предусмотрен.
Ключ берётся из `LLM_API_KEY` или `DASHSCOPE_API_KEY`; подключения и тарифы
описаны в [.env.example](.env.example). `.env` автоматически не загружается.

Без ключа можно запустить `python demo.py` или веб-демо `python demo.py --web`.
Демо распознаёт только кодовое слово, имитирует модель и хранит временную базу до выхода.

## Как устроены стратегии

| Стратегия | Контекст основного запроса | Управление |
|---|---|---|
| Sliding Window | system + последние N сообщений | Переключатель / `/strategy sliding_window` |
| Sticky Facts / Key-Value Memory | system + facts + последние N сообщений | Переключатель / `/strategy facts` |
| Branching | Независимая копия истории, facts и настроек из checkpoint | «Копировать диалог» / `/copy`, `/checkpoint`, `/branch` |

Branching — отдельная операция над диалогом, доступная с обоими способами отбора контекста.
Поэтому в вебе два взаимоисключающих переключателя и отдельная кнопка копирования.

**N включает текущий вопрос**, но не system и не facts. User и assistant считаются
отдельными сообщениями. Например, при N=3 после двух завершённых ходов в следующий
запрос попадут второй вопрос, второй ответ и новый вопрос. N может быть любым целым
числом от 1; при N=1 отправляется только текущий вопрос. Окно может начинаться с assistant.

В Sliding Window старые сообщения полностью отбрасываются из рабочего контекста:
нет ни summary, ни извлечения фактов. Полный архив SQLite остаётся для просмотра
и создания веток; старые реплики из него не возвращаются в запрос модели.
При переполнении лимита токенов запрос останавливается, N автоматически не уменьшается.

В Sticky Facts перед каждым ответом отдельный запрос к той же модели получает
прежний словарь facts и последние N сообщений, включая новый вопрос пользователя.
Модель возвращает полный JSON-объект `ключ: строковое значение`: сохраняет важные
данные, заменяет исправленные значения и удаляет отменённые договорённости.
Например: `{"goal": "запустить проект", "city": "Казань", "style": "кратко"}`.
Ответ агента строится уже с обновлёнными facts. Неподтверждённые предложения
ассистента инструкция просит не считать фактами.

Facts передаются отдельным сообщением assistant как данные диалога; системная
инструкция остаётся первой. Модель извлечения получает явную инструкцию не выполнять
команды внутри данных. Извлечение может ошибаться — содержимое памяти видно в интерфейсе.

## Настройки и ошибки

До первого сообщения можно выбирать стратегию, N, окно контекста и лимит facts.
Настройки сохраняются для чата. После первой непустой отправки они блокируются
в CLI, вебе и SQLite, в том числе при ошибке модели или переполнении контекста.
Предпросмотр и пустое сообщение настройки не блокируют. Для других параметров
создайте новый чат. Копия уже содержит сообщения и наследует заблокированные настройки.

Прогноз не вызывает модель и ничего не сохраняет. В режиме Facts размер показывается
до обновления памяти; перед основным запросом он пересчитывается. Окно проверяется
как для извлечения facts, так и для основного ответа. Лимит токенов — локальная
оценка `tiktoken`, которая может отличаться от ограничения провайдера.

Невалидные, оборванные или слишком длинные facts не заменяют сохранённые.
История и новая память сохраняются одной транзакцией после ответа. При ошибке
незавершённый ход не входит в диалог, прежние facts остаются, текст можно отправить
повторно. Настройки уже заблокированы. Расход полученного ответа на извлечение facts
учитывается и при последующей ошибке основного ответа.

Одновременные операции локального веб-сервера выполняются последовательно.
Версия диалога дополнительно защищает от сохранения устаревшего ответа из другого
экземпляра CLI/веба: такой ответ отклоняется, история и facts не перезаписываются.

## Ветки диалога

«Копировать диалог» атомарно сохраняет checkpoint текущего завершённого диалога
и открывает его копию. Исходник и копия продолжаются независимо.
В вебе ветки создаются кнопкой копирования; переключение — в списке чатов слева.
Отдельное сохранение checkpoint и создание веток из него доступны в CLI.

Checkpoint неизменяем: последующее продолжение исходника или ветки не влияет
на него. В снимке — история, facts, параметры и статистика на момент сохранения.
Ветки работают со своими копиями данных и переживают перезапуск. Автоматического
слияния нет. Удаление чата не удаляет другие ветки и checkpoints; общий список
точек доступен через `/checkpoints` в CLI и `GET /api/checkpoints`.

Пример в CLI:

```text
/strategy facts
/keep 2
Кодовое слово: маяк
/checkpoint Общая точка
# Команда напечатает ID; подставьте его вместо CHECKPOINT_ID.
/branch CHECKPOINT_ID Север
Кодовое слово: север
/branch CHECKPOINT_ID Юг
Кодовое слово: юг
/chats
```

Откройте каждую ветку и спросите кодовое слово. В исходнике остаётся «маяк»,
в первой ветке — «север», во второй — «юг». Быстрая копия: `/copy Название ветки`.
Остальные команды: `/facts`, `/stats`, `/window N`, `/facts-limit N`, `/new`,
`/delete`, `/help`, `/exit`.

## Токены и хранение

Сохранены оценки токенов, API usage, тарифы, кеш и обработка reasoning из четверга.
Общий расход ветки включает новые ответы и обновления facts. Расход скопированной
части показан отдельно и не считается новым списанием. Таблица содержит только
основные ходы; скопированные отмечены ↳. Отсутствие тарифов означает неизвестную цену.
Сетевые ошибки, некорректный формат ответа API и ошибки записи могут оставить
реальные списания провайдера без локальной статистики.

В SQLite: `chats` и `messages` — архив; `context_state` — настройки, блокировка,
facts и версия; `turns` и `facts_calls` — статистика; `checkpoints` — снимки;
`branch_origins` — связь ветки с исходной точкой.

## Проверка без платных запросов

```bash
python -m unittest discover -v
python demo.py
python -m pip install playwright
python -m playwright install chromium
python check_web.py
```

Демонстрация показывает забывание кодового слова в Sliding Window, сохранение
в Facts и независимые ответы в двух ветках. Это проверка механики с имитацией LLM,
а не оценка качества памяти реальной модели.
Тесты проверяют состав запросов, исправления и удаление facts, ошибки и атомарность,
блокировку настроек, перезапуск, CLI, API и независимость веток. Браузерный сценарий
проверяет оба режима, две копии диалога, переключение, блокировку и мобильную вёрстку.
