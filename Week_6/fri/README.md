# Локальный чат с сохранением диалогов

Компьютер с Ollama выступает домашним сервером. В браузере можно создавать и
удалять диалоги; сообщения сохраняются в SQLite и остаются после перезапуска.
С другого устройства в той же Wi-Fi-сети чат открывается по локальному IP.

```text
телефон / другой компьютер
        │  HTTP :8080 + API-ключ
        ▼
локальный чат ── SQLite
        │
        ▼
Ollama (127.0.0.1:11434)
```

Используются стандартные настройки модели Ollama. При отправке новой реплики
модель получает сохранённую историю текущего диалога, чтобы понимать
продолжение разговора.

## Возможности

- создание нескольких диалогов;
- автоматический заголовок по первой реплике;
- переключение между диалогами;
- удаление диалога вместе с сообщениями;
- хранение истории в `data/local-chat.db`;
- Web UI и HTTP API;
- доступ из домашней сети;
- защита API с помощью Bearer-ключа.

Gateway использует только стандартную библиотеку Python 3.10+, поэтому
устанавливать Python-зависимости не нужно.

## Запуск

На устройстве-сервере установите [Ollama](https://ollama.com/download),
запустите её и загрузите chat-модель:

```bash
ollama pull qwen3:8b
```

Затем из каталога `Week_6/fri` выполните:

```bash
python3 server.py init
python3 server.py
```

Команда `init` один раз создаёт игнорируемый Git-файл `.env` со случайным
API-ключом. Сервис слушает `0.0.0.0:8080`, а Ollama остаётся доступна только на
локальном `127.0.0.1:11434`.

Скрипт явно включает UTF-8 для сообщений в терминале. Если старая Windows-
консоль всё равно не показывает русский текст, перед запуском выполните:

```powershell
chcp 65001
$env:PYTHONUTF8 = "1"
py server.py init
py server.py
```

На сервере откройте <http://127.0.0.1:8080>. Вставьте в форму значение
`SERVICE_API_KEY` из `.env`.

## Доступ с другого устройства

Оба устройства должны находиться в одной обычной Wi-Fi-сети. Узнать адрес
сервера:

```bash
# macOS
ipconfig getifaddr en0

# Linux
hostname -I
```

Если адрес сервера `192.168.1.114`, откройте на телефоне или ноутбуке:

```text
http://192.168.1.114:8080
```

Если страница не открывается, разрешите Python входящие подключения в firewall
и проверьте, что используется не гостевая сеть с изоляцией клиентов.

## HTTP API

```text
GET    /health
GET    /api/chats
POST   /api/chats                 {}
GET    /api/chats/{id}
DELETE /api/chats/{id}
POST   /api/chats/{id}/messages   {"message":"Привет!"}
```

Для всех `/api/*` маршрутов нужен заголовок:

```text
Authorization: Bearer <SERVICE_API_KEY>
```

Пример создания диалога:

```bash
set -a
source .env
set +a

curl http://127.0.0.1:8080/api/chats \
  -X POST \
  -H "Authorization: Bearer $SERVICE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{}'
```

## Проверка

Автотесты работают без Ollama и проверяют создание, восстановление, удаление
диалогов, передачу сохранённой истории модели и авторизацию:

```bash
python3 -m unittest -v
```

Интеграционный тест с реальной моделью создаёт временный диалог, отправляет
сообщение, читает его из SQLite через API и удаляет:

```bash
python3 check_service.py
```

Проверка с другого компьютера:

```bash
python3 check_service.py \
  --base-url http://192.168.1.114:8080 \
  --api-key 'ключ-из-.env'
```

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SERVICE_HOST` | `0.0.0.0` | сетевой интерфейс сервиса |
| `SERVICE_PORT` | `8080` | порт Web UI и API |
| `SERVICE_API_KEY` | — | обязательный приватный ключ |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | адрес локальной Ollama |
| `OLLAMA_MODEL` | `qwen3:8b` | используемая chat-модель |
| `CHAT_DATABASE` | `data/local-chat.db` | SQLite-файл с историей |
| `OLLAMA_TIMEOUT_SECONDS` | `300` | таймаут ответа модели |

Для доступа через интернет не открывайте порт `8080` напрямую на роутере:
обычный HTTP не шифрует API-ключ. Используйте приватную VPN-сеть, например
Tailscale.
