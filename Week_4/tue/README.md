# MCP-сервер для Git

Проект реализует собственный MCP-сервер вокруг Git CLI и полноценный чат-агент.
Модель получает описание MCP-инструмента, принимает решение о вызове, а агент
исполняет вызов и возвращает результат модели для подготовки итогового ответа.

## Сценарий

```text
пользователь → ChatAgent → LanguageModel
                         │ tool_call
                         ▼
                  MCP client ── stdio ── Git MCP server ── git CLI
                         │ tool result
                         └──────────────→ LanguageModel → ответ
```

Сервер регистрирует инструмент `git_repository_summary` со входными параметрами:

| Параметр | Тип | Обязательный | Назначение |
|---|---|---:|---|
| `repositoryPath` | `string` | да | путь к локальному Git-репозиторию |
| `commitLimit` | `integer` | нет | число последних коммитов, от 1 до 20; по умолчанию 5 |

Инструмент возвращает корень репозитория, состояние рабочей ветки и последние
коммиты. Git запускается через `ProcessBuilder` без shell-интерполяции.

`ChatAgent` использует тот же интерфейс `LanguageModel`, что и агент прошлой
недели, но без логики памяти, планирования и жизненного цикла задач. Он:

1. запускает Git MCP-сервер отдельным JVM-процессом;
2. получает инструменты через `tools/list` и передаёт их схемы модели;
3. принимает `tool_call` модели и выполняет `tools/call`;
4. добавляет результат как сообщение с ролью `tool`;
5. повторно вызывает модель и показывает пользователю её итоговый ответ.

Доступны CLI и веб-чат. История каждого диалога сохраняется на диск: можно
создавать чаты, переключаться между ними и удалять их. В интерфейсе нет отдельных
панелей рабочей/долговременной памяти, планирования и lifecycle-настроек прошлых
заданий; кроме истории чатов показываются только подключённые MCP-инструменты.

## Требования

- JDK 17 или новее;
- установленный `git`;
- доступ к Maven Central при первом запуске.

## Демо без API-ключа

Из каталога `Week_4/tue`:

```bash
./gradlew run --args="cli --demo"
```

Демо-модель всегда выбирает Git MCP-инструмент, после чего формирует ответ из
его результата. Для веб-интерфейса:

```bash
./gradlew run --args="web --demo"
```

Откройте <http://127.0.0.1:8080>.

## Запуск с моделью

Скопируйте пример конфигурации и заполните ключ OpenAI-совместимого API:

```bash
cp .env.example .env
./gradlew run --args="web"
```

Основные переменные:

| Переменная | Назначение |
|---|---|
| `LLM_API_KEY` | ключ API модели |
| `LLM_API_URL` | endpoint Chat Completions |
| `LLM_MODEL` | идентификатор модели с поддержкой tool calling |
| `LLM_SYSTEM_PROMPT` | общая инструкция чат-агенту |
| `GIT_REPOSITORY_PATH` | репозиторий, доступный инструменту по умолчанию |
| `CHAT_DATA_DIR` | каталог с сохранёнными чатами |
| `WEB_HOST`, `WEB_PORT` | адрес локального веб-чата |

## Проверка

```bash
./gradlew test
```

Интеграционный тест создаёт временный Git-репозиторий, запускает настоящий
MCP-сервер и проверяет полный цикл `модель → tool_call → MCP → tool result →
модель → ответ`, а также сохранение истории. Web-тест проверяет создание и
удаление чатов и отсутствие отдельных панелей памяти или планирования.
