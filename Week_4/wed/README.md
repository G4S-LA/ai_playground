# Новостной агент с расписанием и MCP

Пример задания: «Собирай топ новостей за последние сутки и отправляй мне отчёт
каждый день в 18:00».

ИИ-агент превращает просьбу пользователя в расписание и сохраняет его через
MCP. Системный cron периодически запускает агента. Агент спрашивает у MCP, какие
задания уже пора выполнить, вызывает MCP-инструмент сбора новостей, формирует
отчёт и через MCP сохраняет результат в JSON.

```text
пользователь → ИИ-агент → schedule_news_report → JSON

системный cron → run-due → ИИ-агент → MCP-сервер
                                      ├─ claim_due_news_reports
                                      ├─ get_top_news → Hacker News API
                                      └─ complete_news_report → JSON
                         ↓
                   консоль / webhook
```

Для работы 24/7 постоянный daemon не нужен: команда `run-due` запускается cron,
обрабатывает готовые задания и завершается. Для ручной проверки есть
Web-интерфейс: пока он открыт, встроенный планировщик сам ждёт ближайшее задание.
MCP-сервер в обоих случаях работает дочерним JVM-процессом только во время
общения с агентом.

## Быстрая демонстрация

Нужен JDK 17 или новее. Из каталога `Week_4/wed`:

```bash
./gradlew run --args=demo
```

Команда без API-ключа:

1. через MCP сохраняет одноразовое задание, которое уже пора выполнить;
2. снова обращается к MCP и забирает это задание;
3. получает актуальные новости из Hacker News за последние 24 часа;
4. формирует отчёт, сохраняет его в `data/news-reports.json` и печатает.

Демонстрационная модель детерминированная, но MCP-сервер, расписание, JSON и
данные Hacker News настоящие.

## Работа с ИИ-моделью

Создайте `.env` по образцу `.env.example` и укажите ключ.

### Web-интерфейс

```bash
./gradlew run --args=web
```

Откройте <http://127.0.0.1:8080>. Отдельно запускать MCP-сервер не нужно.
Интерфейс основан на варианте из `Week_3/fri` и содержит:

- несколько сохраняемых диалогов с созданием и удалением;
- чат с реальной ИИ-моделью;
- список расписаний и время ближайшего запуска;
- агрегированную историю отчётов;
- кнопку ручной проверки наступивших заданий.
- кнопку очистки всех расписаний и истории отчётов без удаления диалогов.

Можно написать:

```text
Через 30 секунд пришли мне сводку топ-новостей за последние сутки
```

Агент получает точное текущее время, вызывает `schedule_news_report` и сохраняет
одноразовое задание. Пока Web-сервер работает, он автоматически разбудит агента
в назначенное время. Готовый отчёт появится в том диалоге, где было создано
расписание.

### CLI

Для работы из терминала запустите:

```bash
./gradlew run --args=cli
```

Введите обычную фразу, например:

```text
Собирай топ новостей за сутки каждый день в 18:00 по Москве
```

Агент сам выберет MCP-инструмент `schedule_news_report` и сохранит ежедневный
cron `0 18 * * *`. Команды CLI:

- `/list` — сохранённые расписания;
- `/run-due` — вручную выполнить наступившие задания;
- `/history` — агрегированная история отчётов;
- `/exit` — выход.

## Запуск по системному cron

Сначала соберите обычный запускаемый дистрибутив:

```bash
./gradlew installDist
```

Затем добавьте в `crontab -e` запуск каждую минуту, заменив путь на абсолютный:

```cron
* * * * * cd /absolute/path/Week_4/wed && ./build/install/scheduled-news-agent/bin/scheduled-news-agent run-due >> /tmp/scheduled-news-agent.log 2>&1
```

Cron только будит агента. Точное время (`18:00`) проверяется по расписанию в
JSON, поэтому отчёт выполняется один раз, а не при каждом минутном запуске.

Для проверки без API-ключа добавьте аргумент `--demo`:

```cron
* * * * * cd /absolute/path/Week_4/wed && ./build/install/scheduled-news-agent/bin/scheduled-news-agent run-due --demo >> /tmp/scheduled-news-agent.log 2>&1
```

Ежедневное демонстрационное расписание можно заранее создать через
`./gradlew run --args="cli --demo"`: введите любую просьбу, и demo-модель сохранит
вариант из примера на 18:00. Команда `demo` выше создаёт одноразовый немедленный
запуск. Если готовых заданий нет, `run-due` ничего не собирает.

## Куда приходит отчёт

В Web-режиме отчёт появляется в соответствующем диалоге и в истории справа.
Также он всегда печатается в стандартный вывод команды, который в примере cron
записывается в `/tmp/scheduled-news-agent.log`. Если задан `REPORT_WEBHOOK_URL`,
тот же отчёт будет отправлен POST-запросом в JSON:

```json
{
  "scheduleId": "...",
  "runId": "...",
  "title": "Ежедневный топ новостей",
  "report": "...",
  "storiesCount": 5
}
```

## MCP-инструменты

| Инструмент | Назначение |
|---|---|
| `schedule_news_report` | сохранить ежедневное или одноразовое расписание |
| `list_news_schedules` | показать расписания и следующий запуск |
| `claim_due_news_reports` | атомарно забрать задания, которые пора выполнить |
| `get_top_news` | собрать топ Hacker News за указанный период |
| `complete_news_report` | сохранить готовый отчёт |
| `fail_news_report` | сохранить ошибку выполнения |
| `get_news_report_history` | вернуть агрегаты и последние запуски |
| `clear_news_data` | удалить все расписания и историю отчётов |

Описания инструментов и параметров в MCP-схемах заданы на русском языке. MCP
использует стандартный stdio transport и JSON-RPC; отдельно запущенная команда
`server` ждёт MCP-клиента на stdin/stdout.

## Данные и конфигурация

Расписания, запуски, отчёты и Web-диалоги переживают перезапуск и хранятся в JSON.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_API_KEY` | — | ключ OpenAI-совместимого API |
| `LLM_API_URL` | `https://api.openai.com/v1/chat/completions` | endpoint модели |
| `LLM_MODEL` | `gpt-4o-mini` | модель с поддержкой tool calling |
| `REPORT_DATA_FILE` | `data/news-reports.json` | постоянное JSON-хранилище |
| `WEB_CHAT_DATA_FILE` | `data/web-chats.json` | диалоги Web-интерфейса |
| `REPORT_TIME_ZONE` | `Europe/Moscow` | часовой пояс расписаний по умолчанию |
| `NEWS_CANDIDATE_LIMIT` | `100` | сколько top stories проверить перед фильтрацией |
| `REPORT_WEBHOOK_URL` | — | необязательный адрес доставки отчёта |
| `WEB_HOST` | `127.0.0.1` | адрес Web-сервера |
| `WEB_PORT` | `8080` | порт Web-сервера |

Источник новостей — публичный [Hacker News API](https://github.com/HackerNews/API).
