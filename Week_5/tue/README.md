# RAG-агент на Kotlin

Приложение использует подготовленный корпус документов и SQLite-индекс с эмбеддингами. Агент умеет отвечать в двух режимах:

1. **Без RAG** — вопрос сразу передаётся модели.
2. **С RAG** — вопрос превращается в embedding, из structured-индекса выбираются релевантные чанки, затем вопрос и найденный контекст передаются модели. В ответе модель обязана ставить ссылки `[S1]`, `[S2]`.

Веб-интерфейс показывает оба ответа рядом, время генерации, найденные чанки, их метаданные и similarity score. Там же находится набор из 10 контрольных вопросов и полный автоматический прогон.

## Что используется

- Kotlin/JVM 17 и Ktor;
- Ollama и `bge-m3` для локальных embeddings;
- внешний OpenAI-compatible Chat Completions API для ответов;
- SQLite-индекс, подготовленный модулем индексации документов;
- русские главы книги [«Как создавать AI-агентов»](https://github.com/bojieli/ai-agent-book).

Для запуска понадобятся:

- каталог исходных документов, указанный в `DOCUMENTS_DIR`;
- путь к SQLite-индексу в `INDEX_DB`;
- Ollama на `http://127.0.0.1:11434` только для embeddings;
- OpenAI-compatible endpoint внешней LLM;
- веб-интерфейс на `http://127.0.0.1:8080`.

## Запуск в Windows через MinGW / Git Bash

Сначала установите JDK 17+ и Ollama. Ollama можно скачать обычным установщиком с [официальной страницы Windows](https://ollama.com/download/windows), PowerShell не нужен. После установки откройте Git Bash:

```bash
ollama pull bge-m3

cd /c/path/to/rag-agent

cp .env.example .env
# Заполните .env своими путями, API-ключом, endpoint и моделью.

./gradlew.bat run --args=index
./gradlew.bat run --args=web
```

Приложение автоматически читает `.env` из текущего каталога, поэтому выполнять `source .env` не нужно. Переменные процесса имеют приоритет над значениями файла: отдельную настройку можно временно переопределить прямо в команде.

```bash
WEB_PORT=9090 ./gradlew.bat run --args=web
```

Файл `.env` добавлен в `.gitignore` и не попадёт в репозиторий.

Откройте <http://127.0.0.1:8080>. Команда `index` нужна один раз, а также после изменения документов или embedding-модели. Если индекс уже был построен именно моделью `bge-m3`, этот шаг можно пропустить.

Внешняя модель используется и для baseline, и для RAG-ответа. Отличается только вход: в RAG-режиме к вопросу добавляются найденные чанки. Можно указать любой совместимый endpoint и модель через `LLM_API_URL` и `LLM_MODEL`; ключ также читается из `DASHSCOPE_API_KEY`.

Если нужна полностью локальная генерация, переключите provider обратно на Ollama:

```bash
ollama pull qwen3.5:4b

LLM_PROVIDER=ollama \
OLLAMA_CHAT_MODEL=qwen3.5:4b \
OLLAMA_EMBEDDING_MODEL=bge-m3 \
./gradlew.bat run --args=web
```

Для быстрой проверки без Ollama есть детерминированный demo-режим. Он проверяет весь pipeline и UI, но не даёт содержательных ответов:

```bash
./gradlew.bat run --args="index --demo"
./gradlew.bat run --args="web --demo"
```

> Demo-эмбеддинги имеют другую размерность. После demo-режима перед обычным запуском перестройте индекс через `./gradlew.bat run --args=index`.

## Команды

```bash
# Два ответа прямо в терминале
./gradlew.bat run --args="compare Чем агентный RAG отличается от обычного RAG?"

# Показать набор контрольных вопросов
./gradlew.bat run --args=questions

# Запустить тесты
./gradlew.bat test
```

На macOS/Linux вместо `./gradlew.bat` используйте `./gradlew`.

## Контрольный набор

Файл [`questions.json`](src/main/resources/evaluation/questions.json) содержит для каждого вопроса:

- формулировку;
- ожидание — факты, которые должны попасть в ответ;
- ожидаемые файлы и разделы;
- ключевые термины для воспроизводимой автооценки.

В набор входят вопросы про формулу агента, роли сообщений API, KV Cache, Agent Skills, память пользователя, форматы и типы памяти, базовый pipeline RAG, chunking и агентный RAG. Все они относятся к русскоязычному корпусу из файлов `00-introduction.md`, `02-context-engineering.md` и `03-memory-and-rag.md`.

Автооценка считает:

- долю обязательных понятий в ответах без RAG и с RAG;
- долю ожидаемых источников среди найденных чанков;
- долю RAG-ответов с цитатами.

Это прозрачные эвристики, а не «судья-LLM». Содержательную корректность удобно проверять вручную по двум ответам и раскрытым источникам в интерфейсе.

## HTTP API

```text
POST /api/answer       { "question": "...", "mode": "with_rag", "topK": 5 }
POST /api/compare      { "question": "...", "topK": 5 }
POST /api/index        {}
GET  /api/questions
POST /api/evaluations { "topK": 5 }
GET  /api/evaluations/{id}
```

Полный прогон делает 20 обращений к выбранной LLM (по два режима на 10 вопросов), поэтому для внешнего API учитывайте лимиты и стоимость. Запуск идёт в фоне, интерфейс опрашивает состояние и показывает результаты по мере готовности.
