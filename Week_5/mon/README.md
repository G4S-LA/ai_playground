# Локальный индекс документов на Kotlin

Веб-приложение реализует полный ingestion-пайплайн для `.md`, `.txt`, `.kt`,
`.kts`, `.java` и `.pdf`:

```text
файлы → извлечение текста → chunking → embeddings → SQLite → cosine search
                              ├─ fixed
                              └─ structured
```

Каждый чанк хранит `source`, `title`, `section`, `chunk_id`, стратегию,
тип документа, номер чанка, позицию в тексте, приблизительное число токенов и
номер страницы PDF. Эмбеддинг сохраняется в SQLite как бинарный `FloatArray`.

## Быстрый запуск без Ollama

Нужен JDK 17 или новее. Из каталога `Week_5/mon`:

```bash
./gradlew run --args="web --demo"
```

Откройте <http://127.0.0.1:8080>. Demo-провайдер строит детерминированные
hashing-эмбеддинги и позволяет проверить весь интерфейс без сети и модели.
Это технический режим для демонстрации; для смыслового поиска используйте
Ollama.

На Windows запускайте те же команды из PowerShell через `gradlew.bat`:

```powershell
.\gradlew.bat run --args="web --demo"
```

## Запуск с локальной embedding-моделью

Установите и запустите Ollama, затем загрузите модель:

```bash
ollama pull nomic-embed-text
./gradlew run --args=web
```

На Windows последняя команда выглядит так:

```powershell
.\gradlew.bat run --args="web"
```

По умолчанию приложение обращается к `http://127.0.0.1:11434/api/embed` и
использует `nomic-embed-text`. Настройки задаются переменными окружения из
`.env.example`:

| Переменная | Значение по умолчанию |
|---|---|
| `WEB_HOST` | `127.0.0.1` |
| `WEB_PORT` | `8080` |
| `DOCUMENTS_DIR` | `documents` |
| `INDEX_DB` | `data/document-index.db` |
| `EMBEDDING_PROVIDER` | `ollama` |
| `OLLAMA_URL` | `http://127.0.0.1:11434` |
| `OLLAMA_EMBEDDING_MODEL` | `nomic-embed-text` |

## Работа в Web UI

1. Подготовьте связный корпус объёмом не менее 20–30 страниц: документацию
   одного проекта, статьи, исходники или PDF.
2. Загрузите файлы в первом блоке.
3. Укажите параметры и нажмите «Построить оба индекса».
4. Введите вопрос и нажмите «Сравнить».

Интерфейс показывает для каждой стратегии количество чанков, средний размер,
метаданные результатов, similarity score и исходный текст. Один и тот же
эмбеддинг запроса используется для двух индексов, поэтому результаты можно
сравнивать напрямую.

### Fixed-size chunking

Текст режется окнами одинакового размера. По умолчанию это 1500 символов с
overlap 250 символов. Метод работает с любым текстом, но может разорвать
заголовок, абзац или функцию.

### Structured chunking

- Markdown разделяется по заголовкам с сохранением пути вида
  `Installation > Linux`;
- Kotlin и Java — по верхнеуровневым классам, объектам и функциям;
- PDF — по страницам, затем по абзацам;
- TXT — по абзацам;
- слишком большой раздел дополнительно режется с overlap.

## CLI

```bash
# построить оба индекса из DOCUMENTS_DIR
./gradlew run --args="index both"

# построить только один индекс
./gradlew run --args="index structured"

# выполнить поиск
./gradlew run --args="search structured как запустить проект"
```

Добавьте `--demo` к команде, если Ollama не запущена.

## Web API

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/api/info` | модель и статистика индексов |
| `POST` | `/api/documents` | загрузка файлов в Base64 |
| `POST` | `/api/index` | построение `fixed`, `structured` или `both` |
| `POST` | `/api/search` | поиск по выбранной стратегии |
| `POST` | `/api/compare` | параллельное сравнение выдачи |

SQLite выбран вместо FAISS, потому что учебный корпус содержит лишь сотни или
несколько тысяч чанков. Векторы читаются локально, а cosine similarity считается
линейно. Для такого объёма это быстро, при этом файл индекса переносим и содержит
одновременно эмбеддинги и все метаданные.

## Проверка

```bash
./gradlew test
```

Тесты проверяют границы и overlap фиксированных чанков, иерархию Markdown,
разделение Kotlin-кода, сохранение и поиск в SQLite, а также полный Web API flow:
загрузка документа → построение двух индексов → сравнение результатов.
