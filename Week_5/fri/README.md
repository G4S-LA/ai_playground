# RAG-чат с историей и памятью задачи

Мини-чат на Kotlin, который сохраняет историю сессии, обновляет структурированное состояние задачи и для каждой новой реплики заново обращается к локальному RAG-индексу.

## Что хранится

У каждой сессии есть два уровня памяти:

1. полная история сообщений — исходные реплики пользователя и ответы ассистента;
2. компактная память задачи:
   - `goal` — текущая цель диалога;
   - `clarifiedFacts` — уже подтверждённые уточнения;
   - `constraints` — зафиксированные ограничения;
   - `terms` — пользовательские определения терминов.

История и память находятся в оперативной памяти сервера и удаляются при его перезапуске. Идентификатор текущей сессии сохраняется браузером в `localStorage`.

## Обработка одного сообщения

```text
новая реплика
  → обновление task state и самостоятельный поисковый вопрос
  → semantic search по structured-индексу
  → similarity threshold и heuristic reranking
  → ответ по найденным чанкам
  → проверка source / section / chunk_id и дословных цитат
  → сохранение пары user + assistant в историю
```

Планировщик памяти получает прежнее состояние, десять последних сообщений и новую реплику. Он не отвечает на вопрос, а возвращает JSON с обновлённой памятью и `standalone_question`. Например, короткая реплика «а теперь только локально» превращается в самостоятельный запрос с сохранённой целью.

При штатной работе выполняются два обращения к chat model на реплику:

1. обновление памяти и разрешение ссылок на предыдущий контекст;
2. генерация ответа с обязательными источниками и цитатами.

Embeddings и поиск остаются локальными. Если ответ планировщика памяти повреждён, используется fallback: прежняя память сохраняется, а вопрос дополняется известной целью и ограничениями.

## Источники

Для каждого обычного ответа интерфейс показывает:

- `source`;
- `section`;
- `chunk_id`;
- дословную цитату из чанка.

Метаданные и цитаты проверяет сервер, поэтому модель не может незаметно сослаться на отсутствующий чанк. Если ни один результат не прошёл порог, чат отвечает «не знаю», а блок источников явно сообщает, что релевантные источники не найдены.

Реранжирование выполняется по самостоятельному текущему вопросу, а не по всей истории: термины из старых реплик не должны поднимать нерелевантные чанки. Если две попытки генерации не прошли проверку источников и дословных цитат, чат возвращает «не знаю» вместо случайного фрагмента. Причина отказа и использованный поисковый запрос показываются под сообщением.

Structured chunking выбирает границы по пробельным разделителям, поэтому новые чанки не начинаются посередине слова. После обновления этой логики существующий индекс нужно один раз перестроить кнопкой `Перестроить индекс`.

## Запуск в Git Bash / MinGW

Нужны JDK 17+, Ollama с моделью `bge-m3`, построенный structured-индекс и OpenAI-compatible chat API.

```bash
cd /c/path/to/ai_playground/Week_5/fri
./gradlew.bat run --args=web
```

Регистрировать переменные через `export` или Windows Settings не нужно. Приложение автоматически ищет модельные настройки в следующем порядке:

1. переменные процесса, если они всё-таки заданы;
2. `Week_5/fri/.env`;
3. общий `Week_5/.env` или `.env` в корне репозитория;
4. `.env` соседних модулей, начиная с самого нового.

Таким образом, уже заполненный `.env` предыдущего модуля будет использован автоматически. Из соседнего файла наследуются только настройки LLM и Ollama: старый порт и пути не переносятся. Интерфейс откроется на <http://127.0.0.1:5000>.

Если `.env` ещё нет:

```bash
cp .env.example .env
```

Заполните `LLM_API_KEY`, `LLM_API_URL`, `LLM_MODEL`, а при необходимости пути к документам и индексу.

Построить индекс отдельно:

```bash
./gradlew.bat run --args=index
```

Проверить проект:

```bash
./gradlew.bat test
```

Демонстрационный запуск без внешнего chat API:

```bash
./gradlew.bat run --args="web --demo"
```

В demo-режиме проверяется интерфейс и поток данных, но содержательные ответы внешней модели не имитируются.

## HTTP API

```text
GET    /api/info
POST   /api/index
POST   /api/chats
GET    /api/chats/{id}
DELETE /api/chats/{id}
POST   /api/chats/{id}/messages
```

Пример тела нового сообщения:

```json
{
  "message": "А теперь сравни это с агентным RAG",
  "candidateK": 12,
  "finalK": 5,
  "similarityThreshold": 0.35
}
```
